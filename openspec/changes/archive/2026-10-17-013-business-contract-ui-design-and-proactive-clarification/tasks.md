仅在独立 Review Propose 批准及实际 Apply 指令后实施；实施进展以复选项及实际 Apply instructions 为准。

## 1. Author 方法与产品决定

- [x] 1.1 收敛 Explore 自有方法：稳定约束 / 当前 UI 候选 / 未决产品决定、先查事实和已确认答复、关键未知提问、必要 proof；结合菜单等价调整和非 UI 保留期限未答两类输入核对实际正文，确认不要求普通 UI 新建 Change，也不把等待当批准。
- [x] 1.2 收敛 Propose 自有方法：specs / design / tasks 分工、定稿前复核答案、重要假设不能留给 Apply；用默认截止、草稿改发布、Owner 明确验收 UI 要求核对其处理，保持普通 UI 不新建 Change、不回改历史和无新增审批 / 台账。
- [x] 1.3 随本组复用已有 TypeScript 方法交接测试，验证两个 Author 阶段及修订映射返回真实阶段正文、目标上游和正确角色；仅在实际覆盖缺口处补场景，不新增关键词或镜像测试。语义判断记录在 Apply Run，不以固定证据数量认证方法有效。

## 2. 独立 Review 的同一尺度

- [x] 2.1 收敛 Review Explore / Review Propose 自有方法，分别核对约束 / 候选 / proof 和正式产物 / 答案承接；以“旧顶部菜单词面差异”“重要假设冒充确认”“测试绿但权限或确认缺口”核对正文能同时拒绝机械冻结和业务豁免。
- [x] 2.2 随本组验证 Reviewer 的实际方法内容和无需 Author 上游的边界，复用现有 target-methods / handoff 场景；保持独立角色和固定 Author，不为获取方法伪造完整阶段批准，说明加载成功与语义审核的不同结论。

## 3. 定位修复与用户验证

- [x] 4.1 用当前候选 CLI 在可重建隔离目标取得更新后的真实阶段交接和动态 proposal instructions，保存直接输出；核对正文来源 / 内容、context / rules 和未选 Storybook 路径，不重放旧 Explore 树或修改稳定安装。
