### MVP-D03-C：最小真实交付验收

**范围：**使用 B 的稳定 MenDi 安装，从空目录创建一个 Vue 3 + TypeScript + Vite + Naive UI 项目，作为唯一完整流程目标。官方脚手架只准备空工程，计数器业务在目标 OpenSpec 方案形成并获必要审核后实施；不复制已实现夹具再补造规划历史。最小功能为一个 CounterPanel 的加一、重置与禁用行为，App 只挂载组件；应用与 Storybook 使用同一真实组件。目标拥有 UI 依赖、配置、stories、测试与锁文件，宿主实际调用工具。无 UI 目标仅保留稳定安装、目标路径与真实工程命令验证，直接沿用仍适用的结果，仅补变化或疑点，不组织第二套完整生命周期。默认不修改 MenDi 产品源码，实际接线缺陷才局部修复；不另建方法加载器、通用调度层或第二份目标实现。支持范围限实际验证的 Windows / Node / pnpm / OpenSpec 组合。

**依赖：**MVP-D03-B。

**验收：**稳定 MenDi 入口真实取得 Vue 目标的方法、context / rules 和 instructions，并组织阶段与实际交接，不能仅凭第三方工具运行成功宣称 MenDi 验收成立。唯一目标 Change 围绕计数器的方案、实施、真实独立审核和交付展开，不重复创建已绑定 Change 或重复同步规格。Storybook 使用目标自己的 10.6 官方 CLI、脚本、浏览器与有限交互测试，覆盖初始 / 已有数值 / 禁用状态、加一 / 重置以及源码修改后的新结果；本轮使用无 MCP 路径，不声明 MCP 已认证。真实新 Author 从当前目标、Action、方法和合法 continuing 恢复，完成一个确实未执行的验证任务，不提前完成后重复演示。Vue 保留一次实际 Archive、正式 Full Test 业务失败后的范围内修复、独立定向补审、原完整集合新整次执行及首次 Close，均按各自明确授权执行；根 C Archive、根 D03 正式 Full Test / Close 和 Git 保持后续边界。无 UI 目标不依赖 Storybook / MCP，也不重复上述流程。

**验证：**围绕一份从空目录建立的 Vue 工程，按实际顺序完成空工程准备 → 目标方案 → 计数器与 Storybook 实施 → 新 Author 恢复及修改后验证 → 必要独立审核与获授权的目标收口 → 根 C Review Apply 交接。工程与普通有限测试不能冒充正式 Full Test。实际审核发现问题才修订补审，取消必须制造 changes-requested 或实质修订的演示要求。Reopen、新 Open、旧 PASS 和 unknown 的选择边界沿用 D02-C 仍适用的结论与现有自动化测试，只补接入变化或具体疑点；取消两个目标的第二轮完整交付及无 UI 的完整生命周期，不将取消项记为已执行通过。B 的安装、方法失败边界与无 UI 工程结果直接引用，未变化测试不机械全重跑。目标最终源码、配置、锁文件、OpenSpec 材料及必要结果置于受控位置，.tmp 仅放可重建现场；结果不得误写安装根或无关工程。

真实目标选择与准备须在当时授权范围内确认。LP 仅作为外接职责的架构参照，不预设为已获写入授权的验收目标；其方法生成基线、manager 迁移和运行安装须另行核对与授权，本次规划不授予目标迁移权限。

**阶段安排：**

- **Explore：**仅核对空工程准备、稳定入口、目标 OpenSpec 方法及 Vue / Naive UI / Storybook 的必要接入疑点；可做无业务的静态环境探针，不提前实现计数器、交付生命周期或全部验收。沿用 A / B / D02-C 的适用结论，目的 / 方法 / 结果 / 限制统一写本次 Run，不另建 explore.md。区分普通命令与整组预算；已有 UI 180 秒总入口和纯 tsc 不能未经判断直接用于 Vue 的完整集合与 .vue 类型检查。没有本轮授权不启动子智能体，保持 Author 停独立 Review Explore。
- **Propose：**按上述六个工作分组组织连贯任务，组内按可分别确认完成的工程、角色交接和收口单元拆分，不把一个分组等同于一个 task，也不按单条命令拆任务或 Run。明确保留 / 合并 / 取消及旧结论的适用边界，不恢复碎片化双目标流程。确定唯一目标路径、当前 Change 与阶段入口、独立审核安排、真实新 Author 留待任务、目标 Full Test 原完整集合及执行入口、服务归属与收尾。目标 Open / 新 Change 激活 / Archive / 正式 Full Test / Close 和会话启动按实际缺少的授权集中列出，不推断为根 D03 收口授权。普通 check、有限测试与正式 Full Test 各守用途，不新增选择器、台账、hash、递归引用或数量 gate。
- **Apply / Review Apply：**先创建空壳再形成目标方案，获必要审核后实现计数器与真实 stories，取得真实预览和有限交互结果。保持一份目标实施，不复制旧夹具或补造历史；无 UI 仅补实际工程变化。新 Author 完成真实留待任务，Author 不切换角色自签；目标必要审核由独立 Reviewer 负责，不要求 Owner 逐阶段审核演示项目。获授权后完成保留的目标收口，根 C 汇总有效旧结论、必要新结果、实际未完成项与行数前三，停独立 Review Apply。源码 / 测试 / 脚本只按影响检查，历史 Run 与 verdict 不改，原始输出只保存一份，.tmp 不承担唯一证据。
