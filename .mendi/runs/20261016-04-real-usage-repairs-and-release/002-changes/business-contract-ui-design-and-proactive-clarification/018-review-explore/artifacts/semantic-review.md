# 独立语义反例核对

这是Reviewer对017候选原则的人工推演，不是自动分类器测评或真实UI测试PASS。依据根路线图D04-C、反馈原件和017，逐项检查是否能同时避免“过度冻结UI”和“借UI改动豁免业务”。不代写正式方案。

| 输入反例 | 独立判断及017是否足以约束 |
| --- | --- |
| 旧spec出现“顶部课程菜单”，现改侧栏同能力入口；角色/对象/数据/确认均不变 | 不因旧文字机械要求新Change，不改旧Run/verdict。普通UI调整不新建Change；在当前相关工作记录等价性和必要定位更新即可。017明确区分旧标签与真正承诺，足以支持下一步。 |
| Owner明确把某入口位置/措辞作为验收要求，现按“所有布局都是design”删除 | 不能由模型自行降格。核对当前明确要求；改变承诺的未决取舍先问具体影响。017保留这一例外，不把“需澄清”自动变成“必须新Change”。 |
| “保存草稿”改成“发布”，请求代码没改，但用户会把按钮理解为另一结果 | 名称变化可能影响确认和用户预期，不能仅凭handler相同认定等价；先查实际语义/已确认决定，再决定是否需提问。017的确认条件和可理解/可操作边界可承接，后续方法应表达实际影响而非词表分类。 |
| 页面合并后当前资料可读，历史入口丢失；直达旧URL仍200 | 历史访问/正常可达性缺口，不接受接口成功替代；需真实正常流程与直达分别验收。017已明确。无需在Explore人为搭建无关UI才作出此判断。 |
| 分页改滚动，鼠标测试绿，但键盘无法继续加载；或PDF要求逐页阅读 | “通常是设计选择”不是无条件豁免。按实际目标核对键盘能力及明确功能要求；不存在相关目标时也不强加全设备矩阵。017分别保留这些边界。 |
| 默认截止从空变成当天；服务器拒绝了逾期提交，端到端用例仍绿 | 默认行为已变，必须核对产品决定、时区、请求值、服务器条件；不能以后台校验存在或测试绿补造Owner批准。017要求未知先问且暂停依赖定稿。 |
| 非UI场景：历史数据保留期限不明，模型先写30天，等一分钟后当成同意 | 同样适用主动澄清。查已有决定后仍未知就问影响保留/不可逆结果的问题；等待不是回答，独立调查可继续。该义务来自路线图/反馈的通用约束，不能只在Storybook指导中交付。 |
| Owner已明确普通UI不新建Change，模型为了旧spec词面差异再次要求批准新Change | 不重复询问或倒退已确认决定。017已记载撤回早期过度推断，最后明确答复优先；不能把前次问卷选项当批准。 |
| 选择器失效后force点击、删掉确认步骤断言，保留API用例就声称等价 | 不成立。保留原用户场景、必要技术断言、失败和清理，用当前真实入口定位；017有明确禁止。 |

审核结论：当前方向没有发现阻断Explore的问题。后续Propose仍需把这组边界收敛进实际四阶段方法与相应验收，不得把本表当成实现已完成，也不得靠关键词计数认证方法有效。

现有Author上游有通用澄清原则，但Reviewer不强制读取它；仅保留上游文字不能确保双方同一尺度。合理候选是短的自有四阶段指引及必要定位修复说明，按已有能力组织正式delta；本审核不要求新增CLI状态、问题台账、默认Storybook依赖或全量UI回归。
